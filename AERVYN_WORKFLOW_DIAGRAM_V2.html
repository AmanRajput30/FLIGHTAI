2. Live Flight Data Path

What happens every time your map viewport moves.

sequenceDiagram
  participant C as Client Map
  participant S as Socket.IO Server
  participant F as FlightDataService
  participant O as OpenSky
  participant A as ADSB.lol

  C->>S: viewport_update (map bounds)
  S->>F: request positions in bounds
  F->>O: fetch live positions
  alt OpenSky available
    O-->>F: positions
  else OpenSky down or rate-limited
    F->>A: fetch live positions - fallback
    A-->>F: positions
  end
  F-->>S: bucketed and classified positions
  S-->>C: push position update
  Note over C: interpolate movement, cull off-screen, render

3. Flight Selection Lookup

What fires when you click a flight — three independent lookups, none blocks the others.

sequenceDiagram
  participant C as Client
  participant API as Backend API
  participant ADB as AeroDataBox
  participant AVS as AviationStack
  participant WX as Open-Meteo
  participant PH as Planespotters

  C->>API: select flight (hex)
  par Route lookup
    API->>ADB: get route
    alt AeroDataBox fails
      API->>AVS: get route - fallback
    end
    API-->>C: route data
  and Weather lookup
    API->>WX: get weather at position
    API-->>C: weather data
  and Photo lookup
    API->>PH: get aircraft photo
    API-->>C: photo
  end

4. Auth Flow

Register through to an authenticated, CSRF-protected request.

sequenceDiagram
  participant C as Client
  participant API as Backend API
  participant DB as MongoDB

  C->>API: register - email, username, password
  API->>DB: create user, emailVerified = false
  API-->>C: verification email sent

  C->>API: login - identifier, password
  API->>DB: verify credentials
  API->>DB: create Session and CSRF token
  API-->>C: set _session and _csrf cookies

  C->>API: request to protected route + CSRF header
  API->>DB: validate session and CSRF
  API-->>C: response

5. AI Chat Flow

A chat message, from send to a possible map command.

sequenceDiagram
  participant C as Client Chat
  participant CR as Chat Route
  participant G as Groq - Llama 3.1
  participant S as Socket.IO

  C->>CR: send message + tracked flight hex
  CR->>CR: fetch live telemetry for hex
  CR->>G: system prompt + sandboxed telemetry + message
  G-->>CR: response
  CR->>CR: detect map command in response
  CR-->>C: chat reply
  CR->>S: emit command_focus_map - server only
  S-->>C: map focuses or tracks flight
